## Checkpoint 1

- [x] **Every URL uses the pinned version, not `/stable/`.** All four doc URLs are `/en/latest/`, the build resolved to 9.2. pytest publishes no numeric RTD slug (`/en/9.1.x/` and `/en/9.2.x/` both 404), so `/latest/` is the only non-`/stable/` root; `/stable/` serves 9.1 and was not used. The contributing page's own sidebar self-link points at `/en/stable/contributing.html` — a theme artefact, not followed.
- [x] **No maintainer or triage page marked Full.** The contributing page is the one that would leak: seven of its section headings are maintainer- or triage-only and are named individually in the Reason cell, along with the one paragraph of *Closing issues* that is X-TRIAGE.
- [x] **Partial rows name their in-scope sections.** Both Partial rows list headings on each side, including subsection granularity for *Preparing Pull Requests* and the single-sentence carve-outs in *Report bugs* and *Closing issues*.
- [x] **Config files marked `context-only`, not Partial.** `.pre-commit-config.yaml`, `pyproject.toml`, `tox.ini` and `README.rst` are context-only with the specific keys consulted named.
- [x] **Everything claimed about a file's contents was fetched.** Eleven files came through `seed_sources.py` at `main`; `changelog/README.rst`, `changelog/_template.rst`, `doc/en/backwards-compatibility.rst`, `doc/en/contributing.rst` and `RELEASING.rst` were fetched raw; four doc pages were fetched rendered. `reference/reference.html` is the only row asserting anything without a fetch, and the assertion is only that it is an API inventory, which is what its title and nav placement state.
